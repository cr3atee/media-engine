# Market Terminal: техническая UI-приёмка

Дата: 28 октября 2026 года. Обновлено 30 октября 2026 года.
Статус: автоматизируемая техническая часть пакета 6 завершена; внешние,
юридические и ручные релизные ограничения перечислены отдельно и не считаются
пройденными.

## Проверенный контур

- рабочий каталог `/terminal`, отдельный экран товара и возврат с сохранением
  поиска и фильтров;
- кабинет `/terminal/review`, выбор рабочего пространства, очередь решений,
  подтверждение и восстановление после ошибок;
- четыре продуктовые роли и отзыв доступа в открытой вкладке;
- product-admin-only журнал диагностических инцидентов;
- реальные HTML 404, локальные ошибки, offline/retry и безопасные fallback;
- desktop, ширины `800`, `390` и `320` px, touch/mobile device emulation,
  настоящий browser zoom `200%`, keyboard-only и `prefers-reduced-motion`;
- CDP accessibility tree каталога, товара, проверки объявления и HTML 404;
- быстрые переходы, Back, смена фильтра и плотность 50 карточек под CPU 4×.
- непрозрачный first-paint и межстраничный переход с анимированным знаком,
  аварийным снятием блокировки и отдельным режимом `prefers-reduced-motion`.

## Motion и производительность

На последнем прогоне 50 карточек при CPU throttling 4× зафиксирована одна long
task: максимум и сумма `165 ms`. После стабилизации нет активных конечных анимаций и
элементов с ненулевым `transition: all`. Быстрый переход между площадкой и
поиском сохраняет последнее намерение; предыдущая page animation отменяется.

Reduced motion отключает перемещения и длинные transitions. Журнал диагностики
дополнительно использует мгновенную прокрутку вместо `smooth`. Проверки не
являются обещанием фиксированного FPS на любом устройстве.

## Визуальная проверка

Рабочие страницы используют одну оболочку: одинаковые логотип, шапку, ширину,
поиск, навигацию, типографику, цвета, focus и состояния кнопок. Из кабинета
удалены внутренние пояснения, демонстрационный футер и лишние полноширинные
разделители. Две
карточки каталога выглядят как намеренная компактная подборка; предложения и
площадки читаются до внешнего перехода. Журнал сохраняет табличную плотность на
desktop и перестраивается в последовательные блоки на mobile.

Стартовый экран скрывает незавершённую разметку до окончания начальной загрузки
приложения. Внутренняя полностраничная навигация сначала показывает непрозрачный
слой с центральным знаком Market Terminal; переход не перехватывает SPA-действия
каталога. При отключённом JavaScript содержимое остаётся доступным, а при
`prefers-reduced-motion` декоративное движение отключается.

Повторная проверка 30 октября: кабинет решений прошёл `72/72`, а роли,
управление доступом, диагностика и новый переход — `52/52` browser checks.
Полный Pytest: `668 passed, 60 skipped`; MyPy: `494` файла без ошибок; Ruff,
Ruff format и `node --check` для затронутых файлов прошли. Data-dependent suite
каталога в этом прогоне не пересчитывался: Docker/PostgreSQL локального процесса
были недоступны, а memory-preview содержит другой набор сохранённых реальных
товаров, чем фиксированный acceptance-сценарий. Это ограничение окружения не
выдаётся за успешный прогон каталога.

Реальная 404 возвращает HTTP `404`, использует общую оболочку и предлагает
выходы в каталог и кабинет. API 404 остаётся JSON. Неизвестная ошибка не
показывает traceback или текст исключения.

## Accessibility и эмуляция устройств

Chromium CDP `Accessibility.getFullAXTree` подтверждает доступные `main`,
`search`, названный `searchbox`, кнопки, заголовки, ссылки на площадки, группу
решения, radio controls и поле фактов. Эти проверки выполнены для каталога,
товара, mobile review и HTML 404. Mobile-сценарий использует не только узкий
viewport, но и `mobile: true`, DPR `3`, пять touch points и coarse pointer.

Keyboard-only сценарий отдельно проверяет skip link, поиск, карточки, возврат,
диалог, ошибку формы и восстановление focus. Программный focus нового контента
не рисует рамку вокруг всей страницы, а интерактивные элементы сохраняют
видимый focus ring. Это автоматизированная семантическая проверка, а не замена
ручному прогону NVDA/VoiceOver или тесту на физическом устройстве.

## Открытые релизные ограничения

- юридическая проверка разрешений на брендовые логотипы и обложки не завершена;
  официальный источник и SHA-256 не являются лицензией;
- локальные файлы пяти внешних визуальных ассетов совпадают с реестром SHA-256.
  Повторный GET первичных источников дал точное совпадение для FunPay, GGSEL и
  Microsoft, HTTP 403 для Playerok и новый набор байтов Apple CDN при том же
  размере. Автоматическая замена локальных файлов не выполнялась;
- повторный GET-аудит шести внешних ссылок 28 октября подтвердил HTTP 200 для
  обеих GGSEL и FunPay `25007196`, HTTP 404 для FunPay `80145738` и HTTP 403 для
  обеих Playerok из небраузерного клиента. Playerok остаётся ручной браузерной
  проверкой из-за anti-bot, а FunPay 404 - подтверждённым блокером seed-каталога;
- revision `0020_offer_source_observations` сохраняет source-scoped факты
  доступности и умеет исключать исчезнувшие предложения из public reads, но
  автоматическая сверка выключена до доказанной полной пагинации источника;
- не проведён отдельный прогон screen reader и реальных физических устройств;
- сохранены screenshots и CDP-метрики, но отдельная видеозапись движения не
  создавалась, поскольку в проект не добавляется мультимедийная зависимость;
- административный UI журнала проверяется изолированными fixtures; его backend,
  PostgreSQL, права и restart отдельно проверены пакетом 5A.

Технический контракт доступности, результаты PostgreSQL и точное ограничение
legacy seed-данных записаны в
[`OFFER_AVAILABILITY_LIFECYCLE.md`](OFFER_AVAILABILITY_LIFECYCLE.md).

## Повторный запуск

Нужны локальный сервер на loopback, отдельный Edge/Chromium с CDP на loopback и
Node со встроенным WebSocket:

```powershell
node scripts/verify_terminal_preview_browser.mjs
node scripts/verify_terminal_review_browser.mjs
node scripts/verify_product_access_browser.mjs
```

Verifier-скрипты блокируют внешние origin, не сохраняют credentials в browser
storage и не выполняют мутации рабочей базы.
