# Market Terminal: первый интерактивный предпросмотр

Дата: 2026-10-24. Статус: реализован первый визуальный этап плана перестройки.
Это не выпуск всего нового интерфейса и не новая система авторизации.

## Как открыть

- Новый интерфейс: `/terminal/preview`.
- Пример проверки объявления: `/terminal/preview?screen=review`.
- HTML-страница с настоящим HTTP 404: `/terminal/preview/not-found`.
- Примеры сбоя и отсутствия сети: `?screen=error`, `?screen=offline`.
- Помеченные тесты пустой выдачи и плотности: `?screen=empty`, `?screen=density`.
- «Экраны и роли» открывает навигацию по макетам и четыре продуктовые роли.

Для текущего локального просмотра запущен отдельный процесс на
`http://127.0.0.1:8002/terminal/preview`. Рабочий экземпляр на порту 8001
не перезапускался. PostgreSQL не пересоздавался; live seed runner не запускался.

Повторный запуск использует существующий composition root, без нового runner:

```powershell
# DATABASE_URL должен указывать на изолированную тестовую базу с каталогом.
.venv/Scripts/python.exe -m uvicorn app.main:app --host 127.0.0.1 --port 8002
```

В проверке использована существующая локальная база
`epic23_catalog_review_local` на `127.0.0.1:55433`. Значения секретов в этот
документ не включены. Этот запуск не применяет миграции и не наполняет каталог.

## Реализовано

- Отдельная тёмная оболочка: большой поиск, иллюстрированный баннер,
  компактные квадратные изображения, фильтр площадки, отдельная страница товара.
- Чтение существующего public API. На момент проверки получены два канонических
  товара и шесть предложений GGSEL, Playerok, FunPay.
- Поиск, фильтр площадки, адресное состояние, возврат к выдаче, обработка
  пагинации API, timeout и защита от устаревших ответов.
- Вывод всех предложений с исходными заголовками, продавцами, ценами и ссылками.
  `currency_mismatch` объясняется отдельно. Алгоритм сравнения не изменён:
  frontend не конвертирует валюты и не выбирает своего победителя.
- Макет проверки: исходное объявление и точный целевой товар с ID показаны рядом.
  Факты обязательны для связи/отклонения, необязательны для создания нового товара.
  Подтверждение повторяет товар и объявление; закрытие диалога сохраняет текст.
- Состояния пустой выдачи, 404, неожиданного сбоя, реального отсутствия связи и retry.
  Request ID отображается только при наличии безопасного значения от API.
  Интерфейс не утверждает, что отчёт об ошибке сохранён или отправлен.
- Переход страницы через transform/opacity, открытие диалога, короткая обратная
  связь кнопок и карточек, отмена предыдущей анимации, `prefers-reduced-motion`.
- Локальные шрифт и иллюстрации, прежний строгий CSP без `unsafe-inline`.
  Статические файлы доступны только через явный allowlist.

## Границы предпросмотра

1. Переключение «Пользователь / Партнёр / Модератор / Админ» показывает планируемую
   область ответственности. Оно не выдаёт permissions, не меняет memberships
   и не заменяет серверную авторизацию. Все четыре режима доступны для осмотра
   макета, а не как способ войти под другой ролью.
2. Проверка объявления использует уже связанное предложение из публичного
   каталога как пример. Это не новая рекомендация matching и не рабочая очередь.
   Ни подтверждение, ни создание, ни отклонение в макете не вызывают API мутаций.
3. Постоянный журнал ошибок, frontend reporting и защищённый экран диагностики
   здесь ещё не реализованы. Настоящая ошибка API обрабатывается существующим
   backend; демонстрационные ошибки явно помечены.
4. Для двух известных ID заданы редакционные заголовки только в макете.
   Исходные имена доступны на странице товара и не изменены в доменной модели.
   Для остальных ID используется имя API; автоматической чистки названий нет.
5. Изображения являются иллюстрациями оформления, а не официальными обложками.
   Публичные DTO пока не передают проверенный product artwork.
6. Режим 50 карточек повторяет загруженные товары только в браузере и явно
   подписан как тест плотности. Он не создаёт фиктивные записи или продажи.
7. Старые `/terminal` и `/terminal/review` сохранены. Их поведение не изменено.
   Этот этап не проверяет доступность каждой внешней карточки в реальном времени.

## Проверки

Интерактивная проверка выполнена в отдельном headless Microsoft Edge через CDP.
Добавлен повторяемый скрипт без новых зависимостей:

```powershell
# Требуется отдельный Chromium/Edge с loopback remote-debugging-port=9224.
# Требуется Node 22+ со встроенным WebSocket.
node scripts/verify_terminal_preview_browser.mjs
```

Скрипт допускает только loopback URL. При необходимости адреса задаются через
`TERMINAL_PREVIEW_URL` и `TERMINAL_CDP_URL`. Он закрывает только свою тестовую
вкладку; PNG-снимки создаются в новом каталоге системного TEMP.

Результаты первоначального этапа (до замены обозначений площадок):

| Проверка | Результат |
| --- | --- |
| Браузерные проверки | 39 passed |
| Главная, товар, проверка, 404, сбой | Сняты и просмотрены реальные screenshots |
| Desktop | 1440 × 900; первая строка товаров выше нижней границы экрана |
| Mobile | 390 × 844; дополнительно ширина 320; нет сквозного горизонтального overflow |

58 пропусков относятся к PostgreSQL-проверкам прошлых EPIC: для этого прогона
не задавались `EPIC13_DATABASE_URL`, `EPIC14_DATABASE_URL`, `EPIC15_DATABASE_URL`.
Браузер проверял чтение существующего каталога, а не миграции/контракты этих EPIC.

В полном Pytest присутствует существующее предупреждение Starlette о текущем
использовании httpx TestClient. Зависимости в этой задаче не менялись.

По результатам визуального просмотра исправлены вытянутая мобильная обложка,
лишняя высота баннера и громоздкая мобильная очередь. Обложка теперь квадратная;
объявление на мобильном выбирается компактным native select.

Браузерный прогон не является измерением FPS или INP на настоящем телефоне.
Отдельно ещё нужны полноценный keyboard-only аудит, настоящий browser zoom,
проверка с assistive technology и профилирование кадров при принятии оболочки.

## Уточнение карточек и площадок: 24 октября 2026

Убраны запрошенные подписи о подключённом каталоге, условиях на стороне продавца,
«оригинальных предложениях» и «выдуманных скидках». Важные предупреждения о
валютах, ошибках и макетах сохранены. У заголовка каталога числовой счётчик
загруженных товаров; `+` означает наличие следующей страницы, не полный итог.

В карточке и шапке товара расположен ряд оригинальных логотипов, разделитель,
значок предложений и число. Названия/смысл счётчика доступны через aria-label
и tooltip. Это число предложений, не складской остаток. Ошибка загрузки иконки
не скрывает площадку: включается текстовый fallback.

Public card/detail дополнены полем `marketplaces` со значением по умолчанию `[]`.
Read projection собирает отсортированные уникальные площадки из того же набора
предложений, что и существующие счётчики. Дополнительных запросов на карточку,
новых таблиц, мутаций или изменений matching/comparator нет. Поля `offer_count`
и `marketplace_count` сохранены. Фильтр площадки не меняет состав предложений
у найденного товара: строка показывает все его фактические площадки, как и
существовавшие счётчики.

| Проверка повторного прогона | Результат |
| --- | --- |
| Браузер | 45 passed; отсутствуют runtime/CSP errors; запросы приложения только GET |
| Логотипы и цифры | Состав сверяется с реальным API, дубликатов площадок нет; проверены accessible labels и fallback при ошибке изображения |
| Mobile | Строки площадок помещаются при 390px и 320px; просмотрен отдельный screenshot нижней части карточек |
| Визуальная проверка | Просмотрены desktop-каталог, страница товара и mobile-карточки |
| Полный Pytest | 562 passed, 58 skipped, 1 существующее предупреждение Starlette |
| MyPy | `--explicit-package-bases app scripts tests`: 452 files, ошибок нет |
| Ruff / Ruff format | Изменённые Python-файлы: passed |

Пропуски PostgreSQL-наборов имеют ту же причину, что выше. Реальное чтение
локального PostgreSQL-каталога проверено браузером: два товара, шесть предложений.
Перезапущен только preview-процесс на 8002 для нового read DTO; seed runner не
запускался, решения пользователя и данные каталога не изменялись.

В полном наборе обновлено одно точное ожидание JSON в тесте подтверждения товара:
оно теперь учитывает `marketplaces`. Правила подтверждения и аудита не менялись.

## Следующий этап

Показать этот результат пользователю, затем переносить согласованную оболочку
на рабочие экраны по частям, сохраняя текущие API, реальные правила мутаций,
idempotency и восстановление после 409. Серверная матрица четырёх ролей и
постоянная диагностика остаются отдельными пакетами плана. Визуальный макет
не является подтверждением их готовности.
