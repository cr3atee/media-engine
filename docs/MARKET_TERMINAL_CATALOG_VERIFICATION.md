# Market Terminal: перенос рабочего каталога

Дата: 25 октября 2026. Статус: новая публичная оболочка работает на `/terminal`.
Это завершение переноса каталога, не всего плана перестройки интерфейса.

## Что изменилось

- Шапка с поиском, компактный баннер, квадратные изображения, строка площадок,
  оригинальные логотипы и числовые счётчики перенесены из preview.
- Товар открывается отдельным экраном через прежний `?product=UUID`, а не
  панелью под каталогом. Прямая ссылка и возврат работают; поиск, площадка,
  сортировка и ценовые фильтры сохраняются в URL.
- Прежние фильтры находятся под кнопкой «Фильтры». Неудобная комбинация
  «цена от больше цены до» получает понятную ошибку и фокус в поле.
- Сортировка, категории, пагинация каталога, сравнение, история и снижения цен
  используют существующий клиент public API. Бизнес-логика и DTO не менялись.
- Общее отображение брендов, обложек, чисел цен и fallback вынесено в
  `preview/presentation.js`; рабочий каталог и preview используют одну реализацию.
  Общий CSS сохранён; `catalog.css` добавляет рабочие фильтры и историю.
- У товара доступны исходное название, продавец, цена, ссылка и статус сравнения.
  Разные валюты не пересчитываются и не объявляются общей лучшей ценой.
- Кабинет открывается по прежнему `/terminal/review`. Его HTML, CSS, JS, серверные
  разрешения, tenant context, idempotency и мутации не менялись. Переключателя
  демонстрационных ролей в рабочем каталоге нет.

## Исправления интеграции

При клавиатурной проверке обнаружен повторный запрос каталога после перехода
по якорю `#main`: запоздалый ответ мог скрыть открытый товар. Изменение одного
hash теперь не запускает загрузку каталога. После ответа используется актуальное
выбранное product ID, а не значение до запроса. Клавиатурный сценарий добавлен
в повторяемый browser verifier. Ошибка сети показывается по-русски, с повторной
загрузкой; некорректный ответ не выдаётся за успешный результат.

## Среда и проверка

Проверялась существующая изолированная база `epic23_catalog_review_local`,
loopback `127.0.0.1:55433`. Web-процессы на 8001 и 8002 перезапущены обычным
Uvicorn через существующий `app.main:app`. Seed runner и миграции не запускались.
Для кабинета сохранена прежняя локальная конфигурация auth; секреты не включены
в документ. Изменений данных и решений пользователей эта задача не выполняет.

Повторение browser-проверки, только в отдельном тестовом профиле Chromium/Edge:

```powershell
$env:TERMINAL_PREVIEW_URL = 'http://127.0.0.1:8001'
node scripts/verify_terminal_preview_browser.mjs
```

Скрипт проверяет preview и рабочий каталог, использует только loopback и GET,
временно меняет масштаб отдельного профиля и восстанавливает его. Снимки
сохраняются в новый каталог системного TEMP. Не подключать пользовательский
профиль браузера. Реальные категории и история проверяются без подстановки данных.

## Границы и следующий шаг

- История сохранена как функция, но в текущем каталоге нет точек: показано
  пустое состояние, а не выдуманный график. Категории также не придуманы.
- Прежние ограничения чтения сохранены: 20 предложений и 50 точек истории
  за запрос. Набор из двух товаров не проверяет переход реальной пагинации;
  существующий cursor-код оставлен без изменения.
- Проверялись безопасное отображение ссылок и переходы внутри приложения,
  не текущая доступность карточек на внешних маркетплейсах.
- Исходные наименования не изменены в базе. Два редакционных заголовка/ассета
  привязаны к известным ID; остальные используют имя API и нейтральный fallback.
  Условия публичного использования изображений остаются релизным вопросом.
- Настоящие четыре продуктовые роли, постоянная диагностика и новый рабочий
  кабинет не считаются выполненными. Следующий этап: перенос кабинета с реальными
  действиями, подтверждением точной пары, сохранением комментариев и обработкой
  конфликтов/повторов. Тестовые мутации не должны затрагивать решения пользователя.
