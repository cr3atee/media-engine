# GGSEL Marketplace

## Purpose
Документ фиксирует текущее решение по получению данных GGSEL для MediaEngine.

## Available Data Access Options
На текущем этапе рассмотрены следующие варианты:

- Официальный API GGSEL для публичного каталога: не подтверждён.
- Публичные JSON-эндпоинты каталога: стабильный публичный контракт не подтверждён.
- HTML-страница каталога `https://ggsel.net/catalog`: доступна и может быть получена через HTTP.
- Гидратированные данные фронтенда внутри HTML: присутствуют на странице, но не считаются стабильным публичным API.

## Selected Approach
Выбран безопасный инфраструктурный подход: `GGSelParser.fetch()` получает сырой ответ страницы каталога через существующий `HttpClient`, а `parse()` пока не извлекает предложения.

Это сохраняет архитектуру чистой: получение данных уже работает, но слой извлечения полей не привязан к нестабильной HTML-структуре.

## Why This Approach
На момент review не найден подтверждённый официальный JSON API или стабильный публичный JSON endpoint для каталога GGSEL.

HTML-парсинг не добавляется, потому что структура фронтенда может измениться без предупреждения. Selenium, Playwright и браузерная автоматизация не используются.

## Current Limitations
- Реальные данные можно получить как сырой HTML.
- Преобразование HTML в `ParsedOffer` пока не реализовано.
- Публичный JSON-контракт GGSEL требует дополнительного подтверждения.
- Текущий `parse()` содержит TODO для будущего этапа извлечения данных.

## Next Steps
- Подтвердить наличие или отсутствие стабильного JSON endpoint для каталога GGSEL.
- Если JSON endpoint подтверждён, реализовать извлечение полей только в `GGSelParser.parse()`.
- Если доступен только HTML, отдельно принять архитектурное решение по допустимому способу извлечения данных.
- После подтверждения структуры ответа преобразовывать данные в `ParsedOffer`.
